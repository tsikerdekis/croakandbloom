# Accessibility (a11y) Checklist

> Run through these after each major change. Aim for zero serious or critical issues on every page.

## Landmarks

- [ ] `<header role="banner">` on the site header
- [ ] `<nav>` for primary navigation (with `aria-label`)
- [ ] `<main id="main">` for content
- [ ] `<footer role="contentinfo">` on site footer
- [ ] Skip-to-content link as the first focusable element

## Keyboard

- [ ] Tab order is logical (skip-link → brand → nav → CTA → toggle → content)
- [ ] All interactive elements have a visible focus state (`:focus-visible` rule)
- [ ] Hamburger toggles open/close; Esc closes; focus returns to toggle
- [ ] Lightbox: Esc closes, focus trapped, returns to opener
- [ ] Form fields reachable in order; submit on Enter

## Screen reader

- [ ] Every meaningful image has descriptive `alt`
- [ ] Decorative images have `alt=""` or `aria-hidden`
- [ ] Hamburger toggle announces state via `aria-expanded`
- [ ] Form inputs have associated `<label>` elements (not just placeholders)
- [ ] Form errors announce with `aria-describedby` or `role="alert"`
- [ ] Heading order is sequential (h1 → h2 → h3, no skipped levels)

## Color contrast

- [ ] Body text on background: ≥ 4.5:1
- [ ] Large text on background: ≥ 3:1
- [ ] Link text: ≥ 4.5:1 (test accent color on bisque)
- [ ] Focus outline visible against both light and dark backgrounds
- [ ] Footer (dark on light text): ≥ 7:1

## Motion

- [ ] `@media (prefers-reduced-motion: reduce)` disables transitions
- [ ] No autoplaying video or audio
- [ ] Scroll behavior respects `scroll-behavior: auto` under reduced motion

## Forms

- [ ] `<label for="…">` on every input
- [ ] Required fields marked with `required` and visual indicator
- [ ] Error messages near the field, not just console
- [ ] Formspree `action` URL present, `method="POST"`

## Tools to verify

- `axe DevTools` browser extension — zero serious/critical
- Lighthouse → Accessibility → 100
- `npx pa11y http://localhost:4000/` (CI-friendly)
- Keyboard-only walkthrough of each page
